## 1. 先纠正一个前提

你说「个人主页方面，能设计更多有意思的东西，比如右下角放一个宠物」。

宠物我做了。但这个页面**最大的问题不是「不够花」，是「没有人」**：

| 缺什么 | 证据 | 本轮怎么补 |
|---|---|---|
| **不知道这是谁** | 词标 = `nameFromEmail(ownerEmail)` → `N17852326702`。页面上最大的一个字，是个手机号段。全页没有真名、头像、在做什么 | ② 活的词标 + ④「现在在折腾」 |
| **不知道还在不在更新** | 整页没有任何时间信号。要判断只能逐个点开文章看日期 | ③ 站点脉搏 |
| **没有人味** | hero 是一句通用文案，marquee 是六个英文词，footer 是「一起做点东西。」—— 作品集说明书的语气 | ① 宠物 + ⑤ 彩蛋 + ⑥ 领路 + ⑦ 访客留痕 |

所以宠物是**最显眼的装置，不是唯一的**。七个一起上，页面才真的像有人住。

## 3. 宠物：行为预算才是关键

同样的美术，行为设计差一点就从「这站有意思」变成「这站好烦」。

### 做的六条

| 行为 | 触发 | 为什么做 |
|---|---|---|
| **呼吸** 2.4s | 持续 | 唯一的**持续**信号。没有它宠物就是一张图 |
| **眨眼** 4.2–7.6s **随机** | 持续 | 固定周期会被人脑识别成机械循环，随机才有生命感 |
| **转头看你** | 指针进入 260px 领地 | 提供「它知道你在」的全部价值。是**转头**不是移动 |
| **闻一闻** | 首次到访（localStorage） | 给回访者「它认识我」的暗示 |
| **打哈欠** | 同一段停留 >20s | 信息是「这段挺长，我不催你」—— 把沉默变成陪伴 |
| **伸懒腰** | 滚到底部 | 给阅读一个收尾。唯一「庆祝」性质的动效 |

### 刻意不做的三条

| 不做 | 为什么 |
|---|---|
| **跟随光标** | 实验室里专门做了开关让你感受：打开它，宠物立刻从「住在这里的小家伙」变成「黏着光标的挂件」。而且每帧都在动 → 持续占用合成层、持续索取注意力。**这是宠物设计里最贵的一个诱惑** |
| **自动走动 / 随机跑位** | 会撞到文字。个人主页的首要任务是让人读文章 |
| **发声 / 提醒** | Duolingo 的猫头鹰是这条的反面教材 —— 会催你的吉祥物最终会被讨厌 |

## 4. 位置与降级

### 位置

```
≥1100px          右下角 right:26px bottom:26px，104×104
<1100px          直接隐藏
                 手机上右下角是拇指区，还要跟浏览器工具栏抢位置
文章页回顶按钮    同时出现时，宠物上移到它上方 64px
```

### 降级

| 情形 | 行为 |
|---|---|
| `prefers-reduced-motion` | 呼吸 / 眨眼 / 尾巴 / 耳朵全停 → 静态立绘。转头看保留（200ms 状态切换，不是循环动画）。点它仍会说话。**实验室里有一键对照** |
| 访客手动静音 | 点它睡去，记 `localStorage`；下次直接是睡着的 |
| 站主不想要 | `SiteConfig.pet = null` → 整个装置不渲染 |
| 无 JS / 未水合 | 默认 `hidden`，由 JS 显式打开 → 最坏是「没有宠物」，不是「一只卡住的宠物」 |
| 无障碍 | 整个浮层 `aria-hidden="true"`，不承载必须信息 |

## 5. 为什么不用 emoji / Lottie / GIF

| 方案 | 结论 | 理由 |
|---|---|---|
| emoji 🦊 | ✗ | 这个项目刚花一整轮把 48 处 emoji 换成 53 个线性 SVG。而且跨平台三套字形、不能跟主题色 |
| Lottie | ✗ | 单文件通常 50–300KB，与 `web-ui-bundle-optimize` 冲突 |
| GIF / APNG | ✗ | 无法跟随主题色（三套皮肤会坏）、体积大、不可交互 |
| **单张 SVG + CSS transform** | ✓ | 2–4KB/物种；跟随 `currentColor` 和 token，三套皮肤自动适配；部件独立可动；降级只需停 animation |

**风格上刻意沿用 `Icon.tsx` 的线性语言**（`stroke-width:1.7`、`fill:none`、圆角线帽），只在头身用 `--accent-soft` 补一点体块感。这样它看起来是「这个产品的一部分」，而不是贴上去的贴纸。

## 7. 数据改动（全部可选、向后兼容）

```ts
export interface SiteConfig {
  workNoteIds?: string[];
  blogNoteIds?: string[];
  blogCategoryOrder?: string[];
  // ── 本轮新增 ──────────────────────────────
  displayName?: string;   // ② 词标用真名，缺省回落到邮箱前缀
  now?: string;           // ④ 空则不渲染
  pet?: {                 // null = 完全不要宠物
    species?: 'fox' | 'owl' | 'penguin' | 'otter' | 'whale'
             | 'panda' | 'dolphin' | 'koala' | 'deer' | 'lark';
    name?: string;
    quiet?: boolean;
  } | null;
}
```

**关键：现在所有用户的 `site` 都是 `null`**（我查过两位真实作者），所以新字段必须**缺省即合理**：

- 没配 `pet` → 从 `userId` 哈希派生一个物种 → **每个站主天生就有一只，不用先配置**
- 没配 `displayName` → 回落到现在的行为，不会变差

这跟二阶段「卡片自动封面按 `note.id` 派生」是同一个思路。

**后端零改动**：宠物配置跟着已有的 `POST /api/profile/site` 走。

## 10. 一个诚实的说明：美术是草稿级的

这一轮验证的是**行为系统**，不是美术：

- 4 个物种的 SVG 是我按 `Icon.tsx` 的线性语言（`stroke-width:1.7` / `fill:none` / 圆角线帽）**手写的占位图形**，比例还比较粗糙，狐狸的尾巴偏大
- 真正落地前需要一次插画 pass：统一 10 个物种的体型比例、耳朵/尾巴的辨识度、以及「坐姿」的可爱度
- **好消息是这部分可以完全独立推进** —— 因为行为契约是 `data-pose` / `data-look` / `data-awake` 三个属性，
  美术只要画出零件并标上层级（`.p-head` / `.p-tail` / `.p-eye` / …），行为自动生效，不需要改 CSS

另外，用 `<use href="#id">` 引用外部定义的物种会**渲染成黑剪影** ——
`<use>` 会建 shadow tree，文档样式表里的 `.pet .p-soft` 这类后代选择器跨不过 shadow 边界。
所以这里刻意用内联 SVG。落地时如果用组件化方案，记得把样式写在 SVG 内部或改用 `currentColor` 继承。

## 11. 顺带记录（前几轮已提，仍未修）

1. **词标是邮箱前缀** —— `N17852326702` 是页面上最大的字。建议 `displayName` 缺省时至少做一次「邮箱本地部分 → 更像名字」的处理。
2. **一位作者的 feed 返回空** —— `/api/public/users/ac061a21…/feed` 返回 `{"posts":[],"site":null}`，但同一 `ownerId` 在 `/api/public/feed` 里有 1 篇。个人主页因此对他显示「还没有文章」。
3. **侧栏玻璃没有东西可透**（四阶段记录）—— `.sidebar` 用 `--glass-bg`(62%)、`.topbar` 用 `--glass-bg-strong`(82%)，底下是同色背景。
