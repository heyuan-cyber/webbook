行为预算：为什么是这几条

一个宠物能做的动作有几十种。选哪几条，决定它是「有生命的邻居」还是「屏保 / 玩具」。下面三列是判断依据。

行为做不做为什么
呼吸做唯一的持续信号。没有它，宠物就是一张图；有了它，静止时也「活着」。周期 2.4s —— 比人的静息呼吸略慢，读起来像安静的小动物
眨眼做每 4.2–7.6s 随机（每个实例不同）。固定周期会被人脑识别成机械循环，随机才有生命感
转头看你做指针进入 260px 领地才反应，而且是转头不是移动。这一条提供了「它知道你在」的全部价值
闻一闻做只在第一次来的访客面前触发一次。给回访者一个"它认识我"的暗示，成本是 localStorage 一个 key
打哈欠做读者在同一段停留 >20s 才触发。它的信息是「这段挺长，我不催你」—— 把沉默变成陪伴
伸懒腰做滚到底部触发一次，给阅读一个收尾。也是唯一"庆祝"性质的动效
跟随光标不做打开上面的开关感受一下：它立刻从"住在这里的小家伙"变成"黏着你的光标挂件"。而且它每一帧都在动 → 持续占用合成层、持续索取注意力。这是宠物设计里最贵的一个诱惑
自动走动 / 随机跑位不做会撞到文字。个人主页的首要任务是让人读文章
发声 / 弹出提醒不做Duolingo 的猫头鹰是这件事的反面教材 —— 一个会催你的吉祥物最终会被讨厌

它站在哪：位置与遮挡

桌面 ≥1100px

右下角 right:26px; bottom:26px，尺寸 104×104。
个人主页是满屏 hero + 单列滚动的版式，右下角没有常驻控件（回顶按钮只在文章页），所以不打架。

窄屏 <1100px

直接隐藏。理由不是省事：手机上右下角是拇指区，而且要跟浏览器自己的工具栏抢位置。个人主页在手机上本来就不该有常驻浮层。

和「回顶」的关系

文章页已有 back-to-top。两处都在右下时，宠物让位：贴在同一角落，但回顶按钮出现时宠物上移到它上方 64px。

降级与关闭

情形行为
prefers-reduced-motion呼吸、眨眼、尾巴、耳朵全部停止；宠物变成静态立绘。转头看保留（它是 200ms 的状态切换，不是循环动画）。点它仍然会说句话。可以用上面的按钮预览
访客手动静音点宠物旁的小图标 → 它睡去，记在 localStorage。下次来直接是睡着的，不打扰
站主不想要SiteConfig.pet = null → 整个装置不渲染
无 JS / 首屏未水合宠物默认 hidden，由 JS 显式打开。所以最坏情况是「没有宠物」，而不是「一只卡住的宠物」
无障碍整个浮层 aria-hidden="true"；它不承载任何必须的信息。关闭按钮有 aria-label

成本

项估算
体积单物种 SVG ≈ 2–4KB（未压缩），按需只加载站主那一个。10 个全量 ≈ 30KB，仍远小于一个 Lottie 文件
运行时全部走 CSS transform / opacity，不触发重排。只有指针进入 260px 领地时才挂 pointermove，离开即停；不做常驻 rAF
数据SiteConfig 加一个可选字段 pet?: { species, name?, quiet? }。缺省时从 userId 哈希派生一个物种 —— 所以每个站主天生就有一只，不用先配置
后端零 Worker 改动、零新接口。宠物配置跟着已有的 POST /api/profile/site 走
