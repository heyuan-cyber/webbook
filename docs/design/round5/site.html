为什么不直接用 emoji / Lottie / GIF

方案结论理由
emoji 🦊不用这个项目刚花一整轮把 48 处 emoji 换成 53 个线性 SVG（Icon.tsx）。用 emoji 做宠物是往回走；而且三个平台三套字形，缩放跟随字号、不能跟主题色
Lottie不用单个动画 JSON 通常 50–300KB。项目有 web-ui-bundle-optimize 这一轮专门做过瘦身，冲突
GIF / APNG不用无法跟随主题色（三套皮肤会坏）、体积大、不可交互
单张 SVG + CSS transform用2–4KB / 物种；跟随 currentColor 和 token，三套皮肤自动适配；每个部件独立可动；降级只需停掉 animation

风格上刻意沿用 Icon.tsx 的线性语言：stroke-width:1.7、fill:none 打底、圆角线帽， 只在头身用 --accent-soft 补一点体块感。这样它看起来是「这个产品的一部分」，而不是贴上去的贴纸。

数据改动（向后兼容）

export interface SiteConfig {
  workNoteIds?: string[];
  blogNoteIds?: string[];
  blogCategoryOrder?: string[];
  // ── 本轮新增，全部可选 ──────────────────────────
  displayName?: string;              // ② 词标用真名，缺省回落到邮箱前缀
  now?: string;                      // ④ 「现在在折腾」，空则不渲染
  pet?: {
    species?: 'fox' | 'owl' | 'penguin' | 'otter' | 'whale' | 'panda'
             | 'dolphin' | 'koala' | 'deer' | 'lark';
    name?: string;
    quiet?: boolean;                 // 站主默认让它睡着
  } | null;                          // null = 完全不要宠物
}

关键：现在所有用户的 site 都是 null（我查过两位真实作者，都是 null）， 所以新字段必须缺省即合理： 没配 pet → 从 userId 哈希派生一个物种（每个站主天生有一只）； 没配 displayName → 回落到现在的邮箱前缀行为，不会变差。 这跟上一轮「卡片自动封面按 note.id 派生」是同一个思路。

顺带发现的两个现状问题

问题证据
一位作者的 feed 返回空/api/public/users/ac061a21…/feed 返回 {"posts":[],"site":null}，但同一位在 /api/public/feed 里有 1 篇。个人主页因此对他显示「还没有文章」。前两轮已记录，仍未修
词标用的是邮箱前缀nameFromEmail(ownerEmail) → N17852326702。这是页面上最大的一个字，而它是个手机号段。建议 displayName 缺省时至少做一次「邮箱本地部分 → 更像名字」的处理，或引导站主填一次
