改动 顶栏左侧加 <nav class="nav"> 四项 + 分隔线，面包屑降为「情境信息」跟在后面； 账号菜单只剩 后台 / 皮肤 / 退出。 移动底栏复用同一组 4 项（补上「圈子」）。

为什么推荐它

① 零新概念 —— 4 个去处已经存在于 MobileNav，只是没搬到桌面；
② 一个数据源两种布局 —— 桌面横排、手机底栏，不再是两套集合；
③ 面包屑归位 —— 它本来就只该回答「我在哪」，现在不用兼职导航；
④ 账号菜单变小 —— 只装账号相关，符合用户对「头像」的预期。

战斗演出编辑器架构设计

2026-09-2412 个块

把战斗演出从「帧驱动」改成「时间轴 + 事件驱动」，编辑器侧只描述演出意图，运行时负责插值。

对照方案 轨道承担去处，侧栏纯内容，顶栏只留面包屑 + ⌘K。导航永远可见、永不占顶栏横向空间，代价是多占 68px 且与已敲定的顶栏路线分叉。

什么时候选 B

如果以后要去处变多（比如加「账单」「订阅」「照片墙」），顶栏一行会再次拥挤，那时轨道是唯一还放得下的形态。现在 4 个去处，A 够用。

建议

走方案 A。它是这四个里唯一「顺着已提交的方向再走一步」的选项， 改动集中在一个组件加一份 nav 数据，而且顺带修掉了「桌面比手机弱」这个倒挂。 方案 B 记在这里，等去处超过 5 个时再翻出来。

方案 A 的四个实现要点

要点做法
一份 nav 数据抽 { key, label, icon, to, badge }[] 成共享常量，桌面 <nav class="nav"> 与 MobileNav 都从它渲染 —— 这是「一个数据源两种布局」的落点
当前项判定路由前缀匹配：/app（且非 circles）→ 笔记；/blog → 博客；/app/circles → 圈子；/blog/u/<自己> → 我。规则与 MobileNav 现在的 tab 计算保持一致
窄屏降级≤1080px 时 nav 只留图标（aria-label 保留全称）；≤720px 时 nav 整体隐藏（底栏接手）。面包屑在 ≤900px 时只留最后一段
账号菜单收窄删掉「个人主页 / 社区 / 圈子」三项（已上顶栏），只留「管理后台（管理员）」「页面皮肤」「退出登录」
