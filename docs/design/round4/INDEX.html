核心主张：一份 nav 数据，两种布局

现在的问题不是「顶栏不好看」，是桌面和手机各自维护了一份导航： 桌面把入口塞进账号菜单，手机在底栏摆了 4 个，两份集合还不一样。 解法不是再加一层导航，而是把去处抽成一份数据： 

const PLACES = [
  { key: 'notes',     label: '笔记', icon: 'book',        to: '/app' },
  { key: 'blog',      label: '博客', icon: 'globe',       to: '/blog' },
  { key: 'circles',   label: '圈子', icon: 'users',       to: '/app/circles' },
  { key: 'me',        label: '我',   icon: 'user',        to: '/blog/u/:me' },
];

// 桌面：<nav class="nav"> 横向排（≤1080px 只留图标）
// 手机：<nav class="m-nav"> 底栏竖排（当前 MobileNav）
// 账号菜单：只剩 后台 / 皮肤 / 退出

要你拍板的两件事

Q1 · 导航模型选哪个？

桌面现在没有任何可见的去处，全靠账号菜单。三种模型在 01-nav.html 里可点切换对比。

A. 顶栏 4 个去处 = 移动底栏同一组（推荐） B. 左轨道 68px C. 保持现状，只把账号菜单补上高亮

A 改动集中在一个组件加一份 nav 数据；B 与已提交的顶栏路线分叉；C 等于接受「桌面导航比手机弱」。

Q2 · 这一轮做到哪一步？

五件事彼此独立，可以只挑一部分。

P0 导航统一（01）—— 其余都依赖它 P1 首屏 + 层级（02） P2 公开面去重 + 铺满（03） P3 移动端两个缺陷（04）

我的建议：P0 + P3 先做。P0 是结构性的（后面所有页面都受益）， P3 是两个确定的 bug（390px 实测可复现），加起来改动面很小。 P1 / P2 是观感提升，可以随后。
