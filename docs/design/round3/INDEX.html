设计稿 · 三阶段 · 四版对照

四版气质 + 一套动效层

二阶段给的是一版结构（一体外壳）。这一轮出四种性格，并把动效从「顺手加的几个 transition」变成一套有名字、有职责、可验收的层。 四版共用同一套 DOM 结构，所以可以逐个换、也可以混搭。

四版并排看

版一 / 四

「静」Quiet Craft

去掉装饰只留结构。动效只在状态变化时出现 —— 没有入场、没有错峰、没有视差。

写作三小时不打扰动效预算最低
版二 / 四

「流」Flow

元素之间连得上：卡片长成详情、列表依次到位、滑块跟着手指走。动效负责解释「从哪来、到哪去」。

共享元素动效预算中高
版三 / 四

「沉浸」Cinematic Stage

画布是主角，chrome 变成浮在上面的玻璃片。核心动效是镜头飞行与连线生长。

镜头语言动效预算最高
版四 / 四

「报刊」Editorial

导航退后、排版上前：大衬线、首字下沉、边注。动效全部服务于阅读位置感。

排版驱动动效预算低
贯穿四版

动效规范（可点播）

6 档时长 / 5 条缓动 / 12 条样片，每条都能点、能重播、能一键降级对照。还有 reduced-motion 的保留-去掉清单。

12 条样片降级清单差距映射

动效不是四选一 —— 它是可以拆的

四版里真正互斥的只有视觉气质和导航模型。动效条目之间基本独立，可以按需摘。下面这张表是「哪些能单独拿走」。

动效条目来自可否单独摘说明
镜头飞行版三可以只改 .stage-world 的 transition + 加一个 flyTo()。和视觉气质无关
连线生长版三可以纯 SVG dashoffset，独立于其他一切
共享元素转场版二要改造需要编排层（layoutId / FLIP），但视觉上可以长成版一的样子
列表错峰版二可以改 Reveal 的 API（index + group）即可，任何气质都能用
勾选 / 保存态 / 骨架交叉版一可以「状态确认」类，建议四版都上
滚动进度 + 目录跟随版四可以文章页独立组件，不影响外壳
顶部 tab 导航版四与 Q1 绑定这是导航模型选择，不是动效
无轨道 + 浮层侧栏版三与 Q1 绑定同上

最可能的组合

版一的外壳 + 版二的错峰 + 版三的镜头。 理由：日常写作要安静（版一），但列表第一次出来时可以有一点秩序感（版二错峰）， 而画布上的镜头飞行只在「打开笔记 / 点块」这种低频但关键的动作上出现（版三）。 版四的排版器物（边注、进度线）可以单独放到公开文章页，不影响笔记本。

A · 选哪一版气质 版一「静」／版二「流」／版三「沉浸」／版四「报刊」／混搭 版一 作为默认外壳；版四的排版器物单独给公开文章页；版三 的镜头单独摘出来给舞台
B · 动效层做到哪一档 L1 只做状态层（勾选、保存态、骨架交叉、hover）
L2 = L1 + 秩序层（列表错峰、面板弹出、滑块）
L3 = L2 + 空间层（镜头飞行、连线生长）
L4 = L3 + 连续层（共享元素、页面共享转场） 		建议 L2 先落地。
L1 几乎无感；L2 的错峰是投入产出比最高的一条；L3 的镜头只对舞台用户有意义；L4 成本最高、风险最大，等前三档稳定后单独做

现状问题
.stage-world { transition: transform .14s }平移与缩放共用写死的 140ms，不在任何时长阶上，也没有「程序化飞行」这个概念
.reveal { transition: .5s }500ms 超出「入场 ≤300ms」；位移 14px 是字面值
MOTION (lib/motion.ts)只有 3 档时长 / 2 条缓动；JS 用秒、CSS 用毫秒，两套单位靠人肉同步
4 处各写各的 prefers-reduced-motion容易漏；且大部分是「全关」，没有区分「保留状态 / 去掉过程」
Reveal 的 delay prop能传延迟但没有步长约定，调用方各写各的，也没有封顶
App.tsx 页面转场 y: 88px 是字面值，和 --move-* 无关；不区分「进入更深」与「返回」的方向
