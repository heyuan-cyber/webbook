动效规范：可点播的样片库

这一页不是「更多动画」，是把动效变成一个可讨论、可验收的对象。每一条都能点、能重播、能一键降级对照。所有参数都是 CSS 变量，所以调一个数整站跟着变。

系统当前：正常 ← 这一行的开关作用于整页，随时对比

① 时长阶：6 档，每条都有唯一职责

现在的实现只有 3 档（120 / 180 / 260ms），而且最关键的镜头用了写死的 140ms、段落入场用了写死的 500ms —— 都不在阶上。点每一行听节拍。

--dur-190ms　按压、勾选、微反馈
--dur-2140ms　hover / 选中 / 颜色切换（最高频）
--dur-3200ms　菜单、面板、toast 进出
--dur-4300ms　页面切换、共享元素、抽屉、段落入场
--dur-5480ms　镜头飞行、连线生长、大范围位移
--dur-6760ms　首屏编排、一次性仪式（用一次就够）

两条硬规矩：① 超过 300ms 的动效不许出现在用户高频操作上（打开笔记、切 tab、勾选）；② 时长不随数据量增长 —— 列表有 3 项还是 12 项，总时长都要一样（靠错峰步长反向补偿）。

② 缓动：5 条曲线

--ease-out　cubic-bezier(.16, 1, .3, 1)
进入用。快起慢收 —— 元素「到位」而不是「飘过去」
--ease-in　cubic-bezier(.4, 0, 1, 1)
退出用。慢起快收 —— 让「消失」显得干脆
--ease-io　cubic-bezier(.4, 0, .2, 1)
状态互换用（hover / 颜色）。两端都不突兀，是现在的 --ease
--ease-spring　cubic-bezier(.34, 1.42, .5, 1)
「弹一下」用。曲线越过终点（y<0 段）再回来。只用在 ≤200ms 的小元素上，否则会显得廉价
--ease-stage　cubic-bezier(.22, 1, .36, 1)
镜头专用。比 --ease-out 更平、不过冲 —— 镜头只要有一点点回弹，人就会晕。这是唯一一条为「空间移动」而不是「元素出现」设计的曲线

③ 位移与错峰：两个容易被忽略的参数量

位移距离

--move-12px　按压下沉
--move-26px　提示、气泡
--move-312px　入场
--move-424px　侧滑面板

现在 .reveal 用 14px、.stage-world 无位移、按钮按下无位移、App.tsx 的页面转场用 8px —— 四个数，互相没有关系。位移越大，时长越长：12px 配 300ms，24px 配 400ms 以上。

错峰步长

--stagger-128ms　密集列表（≥12 项）
--stagger-244ms　卡片网格（4~11 项）
--stagger-370ms　分节标题（≤4 项）

必须封顶：20 项 × 28ms = 560ms，最后一项会明显「迟到」。规则是 delay = min(index, 8) × step —— 第 9 项之后全部同时开始。

⑤ reduced-motion 策略：保留什么、去掉什么

「全部关掉」是偷懒。正确的分界是：反映状态的动效保留，表达过程的动效去掉。下面每一条都可以用页面顶部的开关验证。

动效降级后理由
滚动进度线保留它是位置信息，不是装饰。去掉之后用户会失去「还剩多少」的判断
同步状态 morph保留（瞬时）状态必须能看出来。只是颜色不再渐变，直接切换
骨架 → 内容保留（瞬时）避免布局跳变。降级为直接替换，不加淡入
勾选 / 删除线保留（60ms）极短，且是操作确认。全砍掉会让人觉得「没点上」
镜头飞行去掉瞬间到位。用户仍能到达位置，只是没有过程
段落 / 列表错峰去掉内容一次成形，不做位移也不做淡入
共享元素去掉详情直接出现，卡片不「长大」
AI 呼吸 / 微光去掉无限循环动画是前庭不适的主要来源。改为静态文案「生成中…」
面板弹出回弹降级为纯淡入保留「出现了」这个事实，去掉 scale 与回弹
页面转场去掉现在 App.tsx 已经在 reduced 时设 duration: 0，这是对的，保持

⑥ 和现有代码的差距（改哪里）

现状问题建议
layout.css .stage-world { transition: transform .14s }平移与缩放共用写死的 140ms，不在时长阶上；没有「程序化飞行」概念拆成两条：手动 var(--dur-2) + --ease-out；飞行 var(--dur-5) + --ease-stage
layout.css .reveal { transition: .5s }500ms 超出「入场 ≤300ms」的规矩，长列表滚动时会显得拖改 var(--dur-4)，位移 14px → --move-3 (12px)
App.tsx route 转场 y: 88px 是字面值，且和 --move-* 无关用 --move-3；方向按层级（进入更深 → 从上；返回 → 从下）
lib/motion.ts MOTION只有 3 档时长、2 条缓动，且用秒（JS）与 CSS 的毫秒两套单位补齐到 6 档 / 5 曲线，并从一个共享源生成，避免两边漂移
Reveal.tsx 的 delay prop能传延迟，但没有步长约定，调用方各写各的改成 index + group，步长由 --stagger-* 决定，并内置封顶
CSS 里 4 处 prefers-reduced-motion每处各写各的，容易漏归到「token 置零」一个机制上（本设计稿的做法：--dur-* / --move-* / --stagger-* 全置 0/1ms）

一句话总结这一页

动效不是「加多少」，是每条动效都能回答一个问题： 「东西从哪来？」（共享元素、错峰）、「我在空间的哪里？」（镜头）、 「还要多久？」（进度、呼吸）、「刚才成了吗？」（勾选、保存态）。 答不上来的，就不该有。
