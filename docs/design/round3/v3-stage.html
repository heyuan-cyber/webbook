「沉浸」Cinematic Stage

把画布当主角，导航和面板变成浮在上面的玻璃片。动效的核心是镜头：点一个块，视野飞过去；按「适应」，退回全景。连线是画出来的，不是画出来的 —— 它有一段生长过程。

气质

空间感、镜头语言、玻璃

动效预算

--dur-5 (480ms) 镜头 + --ease-stage

参照

Figma / tldraw / Miro

适合

用连线组织知识、把笔记当白板的人

点任意一个块 → 镜头飞过去；点右下「适应」→ 退回全景。鼠标在画布上移动会有一层很淡的光晕跟着（radial-gradient + 260ms 跟随，不是实时跟手）。

③ 生成中的呼吸点我开始 / 停止

呼吸周期 1.15s（不是 1s —— 整秒会让人不自觉地数节拍）。节点边框同时缓入金色，告诉用户「这个块正在被改写」。

④ 块内容回填

AI 生成完的瞬间，块内容不是「跳」出来的：骨架淡出、真内容淡入，同时进行 200ms。块的尺寸变化走 300ms --ease-out，让周围块跟着挪。

代价与风险

项说明
现在最缺的一条没有「镜头飞行」这个概念。StageViewport 里 .stage-world 只有一条写死的 transition: transform .14s —— 平移和缩放共用同一个时长。14ms 的差别在这里很致命：小幅微调显得拖沓，全图适应显得突兀
要做的事把镜头时长做成变量：手动平移/缩放 140ms，程序化飞行（适应视图、聚焦到块）480ms，并区分缓动（手动用 --ease-out，飞行用 --ease-stage）
风险 1玻璃面板 + 网格 + 光晕 = 合成层多。低端机 / 移动端要关掉光晕与 backdrop-filter
风险 2这一版删掉了左轨道，等于同时改了 Q1 导航问题的答案。它需要「⌘K 是主入口」成立 —— 如果你不常用 ⌘K，这一版会不好用
与其他版的兼容镜头动效可以单独摘出来放进版一/版二，不必整版采用
系统当前：正常

关掉动效后镜头会瞬间到位 —— 这是正确的降级：用户仍然能到那个位置，只是没有过程。连线会直接画完。
