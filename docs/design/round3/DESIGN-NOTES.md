## 2. 四版是什么

| 版 | 气质 | 导航 | 动效预算 | 实现成本 | 一句话 |
|---|---|---|---|---|---|
| **版一 静** Quiet Craft | 克制、纸感、字重对比 | 左轨道 + 侧栏 | 200ms 封顶，1 条缓动 | 低（删样式） | 写作三小时之后仍然不打扰你 |
| **版二 流** Flow | 连续、有回弹、层级分明 | 左轨道 + 侧栏 | 300ms + 错峰 28–44ms | 高（共享元素） | 东西从哪来、到哪去 |
| **版三 沉浸** Cinematic Stage | 空间感、镜头语言、玻璃 | 无轨道·浮层侧栏 | 480ms 镜头 | 中高（镜头 + 玻璃） | 画布是主角，chrome 浮在上面 |
| **版四 报刊** Editorial | 衬线、留白、编辑感 | 顶部 tab·无侧栏 | 200ms 用在做滚动反馈 | 低（改 CSS） | 一本你自己的杂志 |

四版**共用同一套 DOM 与 CSS 类**，只有 `[data-v="..."]` 一段不同 —— 所以它们不是在比「谁更好看」，是在比「你要哪种性格」。

### 重叠与真正互斥的部分

```
              视觉气质          导航模型          动效条目
版一 静    ───────────┐   ┌───────────┐   ┌── 状态层（四版都建议有）
版二 流    ───────────┤   │  可 选   │   ├── 秩序层（错峰 / 滑块 / 弹出）
版三 沉浸  ───────────┤   │  其 一   │   ├── 空间层（镜头 / 连线生长）
版四 报刊  ───────────┘   └───────────┘   └── 连续层（共享元素）
                  ↑ 只能选一个        ↑ 只能选一个        ↑ 可以逐个摘
```

**最可能的组合**（写在 INDEX 里）：版一的外壳 + 版二的错峰 + 版三的镜头；版四的排版器物（边注、进度线）单独给**公开文章页**。

## 3. 动效层：这一轮的主要产出

`motion-lab.html` 是一份**可点播的规范**，不是文档。每一条都能点、能重播、能一键降级对照。

### 3.1 时长阶 6 档

| Token | 值 | 用途 |
|---|---|---|
| `--dur-1` | 90ms | 按压、勾选、微反馈 —— 必须「感觉到但看不见」 |
| `--dur-2` | 140ms | hover / 选中 / 颜色切换（最高频） |
| `--dur-3` | 200ms | 菜单、面板、toast 进出 |
| `--dur-4` | 300ms | 页面切换、共享元素、抽屉、段落入场 |
| `--dur-5` | 480ms | 镜头飞行、连线生长、大范围位移 |
| `--dur-6` | 760ms | 首屏编排、一次性仪式 |

两条硬规矩：
1. **超过 300ms 的动效不许出现在高频操作上**（打开笔记、切 tab、勾选）。
2. **时长不随数据量增长** —— 列表 3 项还是 12 项，总时长要一样（靠错峰步长反向补偿）。

### 3.2 缓动 5 条

`--ease-out`（进入，快起慢收）、`--ease-in`（退出，慢起快收）、`--ease-io`（状态互换）、`--ease-spring`（轻微过冲，只用在 ≤200ms 的小元素）、**`--ease-stage`（镜头专用，比 `--ease-out` 更平、不过冲）**。

### 3.3 位移 4 档 + 错峰 3 档

`--move-1..4` = 2 / 6 / 12 / 24px；`--stagger-1..3` = 28 / 44 / 70ms。
**错峰必须封顶**：`delay = min(index, 8) × step`，否则第 20 项要等近 1 秒。

### 3.4 十二条样片

列表错峰、共享元素、命令面板弹出、镜头飞行、连线生长、AI 呼吸、选中滑块、勾选+删除线、保存状态 morph、骨架交叉淡入、底部面板上滑、数字到位。

## 4. reduced-motion：不是「全关」

这一轮把降级策略说清楚了 —— 分界是 **「反映状态的保留，表达过程的去掉」**：

| 动效 | 降级后 | 理由 |
|---|---|---|
| 滚动进度线 | 保留 | 位置信息，不是装饰 |
| 同步状态 morph | 保留（瞬时） | 状态必须能看出来 |
| 骨架 → 内容 | 保留（瞬时） | 避免布局跳变 |
| 勾选 / 删除线 | 保留（60ms） | 极短，且是操作确认；全砍会让人觉得「没点上」 |
| 镜头飞行 | 去掉 | 瞬间到位，仍能到达位置 |
| 段落 / 列表错峰 | 去掉 | 内容一次成形 |
| 共享元素 | 去掉 | 详情直接出现 |
| AI 呼吸 / 微光 | 去掉 | 无限循环是前庭不适的主要来源 |
| 面板弹出回弹 | 降级为纯淡入 | 保留「出现了」，去掉 scale |
| 页面转场 | 去掉 | 现有实现已经在 `reduced` 时设 `duration: 0`，保持 |

实现上建议归到**一个机制**：把 `--dur-* / --move-* / --stagger-*` 全部置 0/1ms，而不是在 4 个地方各写一遍 `@media (prefers-reduced-motion)`（现状就是后者）。

## 5. 和现有代码的差距

| 现状 | 位置 | 问题 | 建议 |
|---|---|---|---|
| `transition: transform .14s` | `layout.css` `.stage-world` | 平移与缩放共用写死的 140ms，不在任何时长阶上；没有「程序化飞行」概念 | 拆两条：手动 `--dur-2` + `--ease-out`；飞行 `--dur-5` + `--ease-stage` |
| `transition: .5s` | `layout.css` `.reveal` | 500ms 超出「入场 ≤300ms」；位移 14px 是字面值 | 改 `--dur-4`，位移改 `--move-3` |
| `y: 8` | `App.tsx` route 转场 | 字面值，与 `--move-*` 无关；不区分进入/返回方向 | 用 `--move-3`；方向按层级 |
| `MOTION` 3 档 / 2 曲线 | `lib/motion.ts` | JS 用秒、CSS 用毫秒，两套单位靠人肉同步 | 补齐 6 档 / 5 曲线，从一个共享源生成 |
| `Reveal` 的 `delay` prop | `Reveal.tsx` | 能传延迟但没有步长约定，调用方各写各的，也没有封顶 | 改成 `index` + `group`，步长由 `--stagger-*` 定，内置封顶 |
| 4 处 `@media (prefers-reduced-motion)` | global.css ×2、layout.css ×5 | 各写各的，容易漏，且大多是「全关」 | 归到 token 置零一个机制 |
