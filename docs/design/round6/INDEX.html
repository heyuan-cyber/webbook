先看现状：六层里四层是空的

我把个人主页现在的交互全部翻了一遍（UserBlogPage.tsx / site/*.tsx / layout.css）。 用一个六层框架来看，缺口非常清楚。

1排版动效 让内容「到位」。入场、错峰、绘制、字标编排。建立阅读节奏，不承载信息 部分 · Reveal / marquee
2反馈动效 让操作「被确认」。hover / press / 波纹 / 磁吸 部分 · 卡片 hover
3空间动效 让页面有「深度」。视差、倾斜、光标光晕、点击涟漪 空
4内容动效 让数据「可读」。更新热力、数字到位、阅读进度、栏目占比 空
5角色动效 让页面有「住户」。宠物、彩蛋、领路、签名 空 · 五阶段已设计
6时间动效 让页面有「当下感」。深夜文案、节日、第 N 次来访、纪念日 空
代码事实说明
hooks/ 只有 1 个文件只有 useMediaQuery.ts。没有任何交互相关的 hook —— 说明交互能力现在是散在各组件里手写的
reduced-motion 有两套机制useMotionSafe()（9 个文件）+ Reveal.tsx 里直接 matchMedia 一次。两套写法意味着迟早会漏
动效 token 只有时长和缓动lib/motion.ts 里 3 档时长 / 2 条缓动，没有位移距离、没有错峰步长 —— 这两个恰恰是最容易写歪的
没有「关闭交互」的出口访客除了改系统设置，没有任何办法让页面安静下来

交互层的三个组成

要让「支持更多交互效果」变成可扩展的事，而不是一条条加功能，需要把交互拆成 触发器 × 效果 × 约束 三件东西。 新增一条交互 = 组合一个触发器和一效果，而不是写一个新组件。

① 触发器：访客做什么（10 个）

触发器含义现状个人主页上的可能用法
hover指针悬停元素已有卡片抬起、词标乱码归位、脉络格悬停出日期
near指针进入元素周围 R 半径新磁吸按钮、光标光晕、宠物转头
scroll:enter元素进入视口Reveal区块入场、数字到位、连线绘制
scroll:progress滚动进度 0–1文章页有阅读进度线、视差、顶栏 morph
scroll:idle停在同一个位置超过 N 秒新宠物打哈欠、「要不要我带你逛逛？」
click点击 / 轻触已有涟漪、揭示隐藏段落、宠物说话
clock本地时间（时段 / 整点 / 节日）新深夜换文案、节日换词标、周年
visit:nth第几次来访（localStorage）新第二次来宠物先看你、第五次提示订阅
key键盘输入新输入 he 触发签名动画（彩蛋）
hashURL 里带特定 hash新揭示「只发给某个人」的段落

② 效果：页面怎么回应（12 个）

效果类型成本说明与参数上限
rise装饰极低位移 + 淡入。位移 ≤12px、时长 ≤300ms
stagger装饰极低错峰。步长 28/44/70ms 三档，必须封顶第 8 项
parallax装饰低分层不同速率。速率差 ≤2×，只写 transform
tilt装饰低3D 倾斜。≤6°，perspective ≥600px
magnetic装饰低光标吸引。半径 ≤140px、位移 ≤8px，热区不动
spotlight装饰低光标处柔光。跟随缓动 ≥200ms（不要实时跟手）
scramble装饰极低文字乱码归位。纯文本替换，同次悬停只播一遍
draw装饰低路径绘制。dashoffset，≤480ms
pop装饰极低数字到位。300ms 过冲，不做 0→N 计数
morph功能低形态过渡。只改颜色/边框/阴影，不改高度
character装饰中角色行为。见 五阶段 —— 整套行为预算已经定好
heatmap功能极低数据可视化。颜色是信息，降级时保留
reveal功能极低条件显示内容。注意不是权限，别放隐私

③ 约束：每条交互都必须满足（7 条）

约束规则
① 可分类每条交互声明 kind: 'functional' | 'decorative'。这是所有降级策略的前提 —— 分不清就只能一刀切全关，那会连阅读进度一起砍掉
② 可关闭访客能一键关掉全部装饰型，记 localStorage。现在的代码里没有这个出口
③ 不挂空监听关闭时根本不注册监听，而不是"注册了但不执行"
④ 不用常驻 rAF只在事件里 rAF 节流；空闲即停。宠物也只在指针进入领地时才挂 pointermove
⑤ 移动端有替代触屏没有 hover → 依赖 hover/near 的交互在 ≤720px 直接不挂载（不是降级成 tap，那会误触）
⑥ 不挡内容装饰层 pointer-events:none；位移只改视觉，点击热区永远不动
⑦ 首屏不阻塞交互层在 hydration 之后挂载；无 JS 时页面完整可读，只是不动

组合：新增一条交互应该只是填一个对象

这是「支持更多」的关键 —— 不是再加一个组件，而是让交互变成数据。

type Kind = 'functional' | 'decorative';

interface Interaction {
  id: string;                 // 'hero-parallax'
  target: string;             // 语义槽位：'hero' | 'card' | 'wordmark' | 'pulse' …
  on: TriggerKind;            // 'hover' | 'near' | 'scroll-enter' | 'clock' | …
  do: EffectKind;             // 'rise' | 'parallax' | 'tilt' | 'character' | …
  kind: Kind;                 // 决定它在降级时是留下还是消失
  params?: Record<string, number | string>;
  minWidth?: number;          // 低于此宽度不挂载（触屏没有 hover）
}

// 四条真实交互，拆开看都只是"一个触发器 + 一个效果"
const HOMEPAGE: Interaction[] = [
  { id: 'hero-parallax', target: 'hero',     on: 'scroll-progress', do: 'parallax',
    kind: 'decorative', params: { layers: 3, maxRate: 1.8 } },
  { id: 'card-tilt',     target: 'card',     on: 'hover',           do: 'tilt',
    kind: 'decorative', params: { max: 6 }, minWidth: 721 },
  { id: 'pet',           target: 'corner',   on: 'near',            do: 'character',
    kind: 'decorative', params: { species: 'fox', radius: 260 }, minWidth: 1100 },
  { id: 'read-progress', target: 'article',  on: 'scroll-progress', do: 'morph',
    kind: 'functional' },
];

站主视角：预设包，不是 20 个参数

站主不该被要求配 20 个参数。给三个预设包 + 个别开关就够：

安静 quiet · 默认

只有功能性交互 + 区块入场。没有视差、没有倾斜、没有光晕、没有宠物。
= rise · stagger · morph · heatmap · reveal

有反应 lively

在安静之上加空间层：视差、卡片倾斜、光标光晕、词标乱码。
= quiet + parallax · tilt · spotlight · scramble

玩心 playful

在「有反应」之上加角色与时间层：宠物、磁吸按钮、深夜文案、hash 彩蛋。
= lively + character · magnetic · clock · hash

配置形态

SiteConfig.interactions = {
  preset: 'lively',
  disable: ['card-tilt'],   // 关掉预设里的某几条
  params: {
    'pet.species': 'owl',
    'hero-parallax.maxRate': 1.4,
  },
}

落地形态：4 个文件，不是 20 个组件

新增职责
lib/interactions/catalog.ts触发器枚举 + 效果枚举 + 每条效果的参数上限（tilt ≤6°、magnetic ≤8px 这类约束写进类型里，而不是写在注释里）
lib/interactions/presets.ts三个预设包 = 三份 Interaction[]
hooks/useInteractions.ts读 SiteConfig.interactions → 解析预设 → 统一判断 reduced-motion / 访客关闭 / 断点，再挂载。当前那些散在各处的 useMotionSafe() 收敛到这里
components/FxToggle.tsx页脚那个「让页面安静下来」的开关，写 localStorage
layout.css 追加把 --stagger-* / --move-* 补进 token（现在只有 --dur-* / --ease*）

注意这 4 个文件没有一个在加新功能 —— 它们只是把已有的交互收进一个可查询、可批量开关、可配置的层。 之后再加「点击涟漪」「节日词标」「栏目占比环」都只是往 catalog 里加一条。

要你拍板三件事

Q1 · 交互层的边界划在哪？

这决定了要建多少基础设施，也决定了站主能配多少。

A. 建交互层（catalog + presets + useInteractions），交互变成数据（推荐） B. 只补几条高价值交互，不做抽象 C. 只做约束与降级（分类 + 关闭开关），交互照旧一条条写

A 是唯一能回答「支持更多交互」的方案；B 半年后又是一堆手写；C 解决不了扩展，但成本最低。

Q2 · 默认预设选哪个？

新站主默认拿到哪一档。

安静 quiet（默认） 有反应 lively 玩心 playful

我建议默认 quiet：个人主页第一任务是让人读文章。想要花哨的站主自己去设置里开。

Q3 · 访客的「安静开关」放哪？

现在代码里完全没有这个出口。

A. 页脚一行文字链「让这个页面安静下来」（推荐） B. 右下角常驻小图标 C. 只跟随系统 prefers-reduced-motion，不给手动开关

A 不占视觉、能被找到、也不打扰；B 又变成一个浮层要管理；C 等于把责任推给用户的系统设置。
