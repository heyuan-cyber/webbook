让这个页面安静下来

三档到底差在哪

安静（默认）—— 站主不选时的样子

页面上没有任何装饰型交互。剩下的是：顶栏滚动 morph、阅读进度、站点脉搏、条件显示。 这些是功能型 —— 关掉会丢信息，所以它们在所有档位里都在。

选它的理由：个人主页第一任务是让人读文章。prefers-reduced-motion 用户看到的就是这一档，所以它必须是能独立成立的，而不是"别档砍掉动效后的残骸"。

有活力 —— 加上空间层 你正在看这一档

新增现在可以去试
hero 视差在预览区里滚动 —— 网格 / 内容 / marquee 三层不同速率（0.4× / 0.85× / 1.6×）
光标光晕鼠标在 hero 上移动，一圈柔光跟着走（260ms 缓动，不是实时跟手）
卡片倾斜悬停卡片，最大倾斜 6°
词标乱码鼠标移到「何源」上，字符短暂重排再归位

这一档的边界：全部是「光标在哪里 / 滚到哪里」的即时反馈， 没有一个元素会自己动。所以它不会在你读文章时分心。

玩心 —— 加上角色与时间层

新增现在可以去试
驻站宠物右下角那只。鼠标靠近它会转头看你（不跟随）；整页滚动它一直待在那儿
CTA 磁吸鼠标靠近「查看项目示例」，按钮被吸过去（上限 8px，点击热区不动）
卡片涟漪按下任意卡片，从按点扩散一圈

这一档开始有「自己会动的东西」（宠物），所以才需要访客关闭开关 —— 见 settings.html 里那个页脚链接的设计。

三档的成本与风险

档位合成层与监听低端机 / 移动端最怕的用法
安静 无新增合成层；只有滚动监听 无风险 站主觉得"太素"，跑去手写一堆动效 —— 那就绕过了整个约束体系
有活力 视差 3 层 + 光晕 1 层；指针监听 3 处，均 rAF 节流 ≤720px 全部不挂载 视差速率差开到 2× 以上，页面会显得"散架"
玩心 再加宠物（CSS 动画 1 层）+ 涟漪（点击时临时节点） 宠物 ≤1100px 不显示 把宠物做成"会催人的吉祥物" —— 五阶段已经论证过这条是反面教材

同一份 DOM 是怎么做到的

<!-- 只改这一个属性 -->
<div class="site-body" data-preset="lively">

<!-- 元素自己声明"我属于哪一档" -->
<div class="hero-grid"  data-par-depth="0.4"></div>          <!-- 只在 lively+ 生效 -->
<div class="pet-dock fx-playful"> … </div>                    <!-- 只在 playful 显示 -->
<h1 class="hero-word fx-lively">…</h1>                       <!-- 同上 -->

/* CSS 门控 —— 三行搞定 */
[data-preset="quiet"]  .fx-lively,
[data-preset="quiet"]  .fx-playful,
[data-preset="lively"] .fx-playful { display:none !important }

/* JS 里每次触发都实时读 preset，不缓存 */
function presetOf(el){ return el.closest('[data-preset]').dataset.preset }

关键点：JS 在挂监听前要判断两件事 —— 元素是不是被门控掉了（offsetParent === null），以及当前档位是否需要它。 六阶段的约束③「关闭时根本不注册监听」在这里落地成：decoOff() || presetOf(el) === 'quiet' 直接 return。
