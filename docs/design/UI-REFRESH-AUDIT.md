# WebBook 界面美化 · 现状审计与设计方向

> 产物：设计稿（可点开看的静态页面）在 `docs/design/mockups/`，先看 **[mockups/INDEX.html](mockups/INDEX.html)**。
> 本文是设计稿的"为什么"：现状证据、问题清单、三个方向的取舍。
> 审计基准：`apps/web/src/styles/global.css`（521 行，SHA 9E635FEF…）+ `layout.css`（5 657 行 / 130 KB，SHA EF9D1E41…）。
> 截图证据：`docs/design/mockups/_before/`（1600×1000 桌面 + 390×844 移动，headless Chrome 实拍）。

---

## 1. 一句话结论

WebBook 的**功能密度已经很高**，但界面被"六代首页 + 两套设计语言"拖住了：
token 体系只覆盖了外壳，**真正在用的排版/间距/圆角/颜色大部分是硬编码**，
而**画布与图谱层偷用了另一套冷色系**（slate/blue），所以产品看起来像两个 App 拼在一起。

不需要推倒重来。核心动作是 **把 token 体系补全并真正接入**，
再收口导航层级、侧栏深度、图标体系这三件具体的事。

## 2. 现状证据（可复核）

### 2.1 token 体系"名存实亡"

`global.css` 定义了完整的 token，但 `layout.css` 里几乎不用：

| Token 族 | 在 layout.css 的使用 | 同位置的硬编码 |
|---|---|---|
| `--fs-*`（字号阶） | **0 次** | **188 处 px 字号**（10/11/12/13/14/15/16/18/20/22/26px 共 11 种） |
| `--space-*`（间距阶） | **0 次** | padding 249 行 / margin 203 行 / gap 187 行 |
| `--radius*` | 39 次 | **116 处 px 圆角**（2/3/4/6/8/10/12px + 999px×15） |
| `--shadow-*` | 23 次 | 28 处手写 box-shadow |
| `--accent*` | 139 次 | 8 处金色 rgba 用"自己算的透明度"（.06/.08/.12/.22/.28/.35） |
| `--z-*` | 6 次 | 40 处裸 z-index |

最典型的浪费：`12px` 字号用了 58 次、`13px` 46 次、`11px` 30 次——
它们分别对应"次级信息 / UI 文本 / 微标签"三种角色，却没有角色名，改一次要动几十处。

### 2.2 两套设计语言混在一起（最伤观感的问题）

| 区域 | 配色 | 是否走 token |
|---|---|---|
| **A. 外壳 / 侧栏 / 编辑器 / 后台 / 圈子 / 任务** | 暖金 `#c4a574`、`--bg #14161a`、玻璃拟态 | ✅ 唯一走 token 的 |
| **B. 博客 / 长文** | 同暖金 + 衬线 | 颜色走 token，**字号全硬编码**（18px） |
| **E. 画布 / 连线图 / 节点 AI 条 / 3D** | **冷蓝 `#38bdf8`、slate `#334155/#1e293b/#0f172a`、`#0b1220`** | ❌ 完全另一套 |
| **F. 个人主页** | 纯黑 `#000` + 蓝 `#3b82f6` + Playfair | ❌ 自带 `--s-*` 孤岛 |

**A 是暖金、E 是冷蓝**，而 E 恰恰是 WebBook 的招牌功能（舞台/连线成图）。
更危险的是 E 的冷色是**藏在 `var(--token, #hex)` 兜底值里**的：

```css
/* layout.css 3432 */ box-shadow: inset 0 0 0 1px color-mix(… var(--accent, #38bdf8) …);
/* layout.css 3948 */ background: var(--surface, #1e293b);
/* layout.css 4032 */ color: var(--muted, #94a3b8);   /* --muted 这个 token 根本不存在 */
```

一共 **33 处这种兜底**，外加 `--muted` 是拼错的 token 名（真名 `--text-muted`），
意味着 `#94a3b8` 永远生效。**一旦有人重命名某个 token，画布会无声地变成 Tailwind slate 蓝。**

实测截图对比（`_before/`）：截图里外壳是暖金玻璃（`08-local-app.png`），
而画布区 `--stage-bg` 是 `#0b1220`（深海军蓝）——同一屏里两个色温。

### 2.3 侧栏：深度一上来就撑爆

你的真实目录（从运行中的 `/app` 读出）**有 6 级嵌套**：

```
📁 基础游戏开发 / 📁 渲染开发 / 📁 基础 / 📁 Gameplay开发
  / 📁 战斗演出 / 📁 通用编辑器 / 📁 新栏目     ← depth 6
    📄 战斗演出编辑器架构设计                    ← depth 7
```

侧栏固定 `--sidebar-w: 300px`，行内缩进 `paddingLeft = 8 + depth × 14px`。
到 depth 7 时缩进 106px，**只剩 190px 给文字 + 悬停工具按钮**，
而预览态一行内文本用 `13px`、按钮 5 个 22×22——必然截断或换行。

这不是"多写点 CSS"能解决的，是**信息架构问题**：目录需要
(a) 可调宽度 / 可拖拽，(b) 面包屑补偿缩进，(c) 深层级折叠策略（只展开当前路径）。

### 2.4 顶栏：7 个平级入口，没有主次

`AppShell.tsx:81-130` 实测渲染：

```
☰ | 游客模式 / 邮箱                    社区 · 个人主页 · 任务 · 圈子 · 后台 · 退出 · [登录]
```

问题：
- **7 个平级 ghost 按钮**，`flex-wrap: wrap`，窄屏折成两行且高度不齐（primary 登录 vs ghost 链接混排）。
- **没有 active 态**：`.btn-ghost.active` 定义了但没人用；在 `/blog`、`/admin`、`/app/circles` 里看不出自己在哪。
- **`后台` 对游客也显示**，点进去只得到一张"需要管理员权限"卡片。截图 `06-admin.png` 就是这个空转。
- **移动端 390px 只剩「社区」**（`11-app-mobile.png`）：登录/退出/个人主页全被挤掉，**没有底部导航**。
- **Ctrl+K 命令面板只在 `/app` 有**（`CommandPalette` 挂在 `AppShell` 内），
  而 `AppShell` **只被 `UserApp.tsx` 一个页面使用**——`/blog`、`/blog/u/*`、`/app/circles`、`/admin` 全都没有侧栏、没有顶栏、没有 Ctrl+K。

### 2.5 图标：48 处 emoji / 字符当图标

`📓` logo、`📁/📄` 目录、`＋ ❏ ☑ ✎ 🗑` 行内工具、`☰`、`⠿` 拖拽、`✕` 删除、`▸/▾` 折叠、
`🤖` AI、`🛠` 后台、`⟳` 刷新、`🔒/👥/🌐` 可见性（还在 `<option>` 里）、
`blockFactory.ts:69-77` 更把 `立方` 这个**中文词当图标**用。

后果：跨平台渲染不一致（Windows/macOS/Android 三套 emoji 字形）、
无法跟随主题色、无法控制视觉重量、`font-size` 一变图标就跟着变（外壳里出现过 10/12/16/18/20px 五种）。

### 2.6 排版层级混乱：同一个 H1 有四个尺寸

| 位置 | 实际字号 | 来源 |
|---|---|---|
| token 定义 | `2rem` = 32px | `global.css --fs-h1` |
| 编辑器内 H1 块 | **26px** | `layout.css:1069` |
| 博客渲染 H1 | **1.85rem ≈ 29.6px** | `layout.css:2568` |
| 移动端笔记标题 | **20px** | `layout.css:3255` |

"区块标题"这个角色有 6 种写法（`.plan-head h2` 16px/600、`.blog-card-title` 650、
`.blog-a-h` 650、`.es-title` 1.25rem/600…）。
`.es-title` 用的是 `<h3>`，在空侧栏里它就是整页最高级标题——但语义上是 h3。

### 2.7 首页背了六代

`layout.css` 里同时躺着 v4（139 行）、v5 霓虹（75 行）、io-* 沉浸式（263 行）、
blog-home-v2（45 行）、io-site 多标签（525 行）、Swiss 纯黑（515 行）——
**首页共吃掉约 19% 的样式表**，其中 ~9% 可确认是死代码，
`.io-card`、`.btn-sm`、`.settings-group input`、`@keyframes io-bob` 都是**定义两遍，前面那遍无效**。

> 改"卡片长得怎么样"时改第 2448 行不会有任何效果——真正生效的是第 4581 行。
> 这类陷阱会让后续每次美化都踩坑。

| 位置 | 问题 |
|---|---|
| `layout.css:572` | AI 用户气泡是**金色底 + 冷青文字 `#04222f`**（token 是暖黑 `#1a1510`） |
| `layout.css:3425` | 画布底色 `#0b1220` 与外壳 `#14161a` 不同色温 |
| `layout.css:3737` | 连线 `stroke: #38bdf8` 冷蓝，与金色选中态打架 |

## 3. 三个美化方向（设计稿已出）

三份设计稿都覆盖同样 9 个界面，只有"语言"不同，方便直接对比。
每份都带 **token 定义表**，确认后可以直接抄进 `global.css`。

### 方向一 · 墨金（Warm Editorial）— 推荐

**在你既有气质上做"减法 + 补全"**，风险最低，改动可控。

- 保留暖金主色与暗色底，但**去掉大范围玻璃模糊与极光动效**：
  长时间写作时背景不再"呼吸"，视觉噪声下降明显。
- 建立**完整字号阶与间距阶**并真正接入（消灭 188 处硬编码字号）。
- 画布/图谱层**从冷蓝改为暖石墨 + 金色连线**，与外壳统一为一个产品。
- 侧栏支持**拖拽调宽 + 深层级只展开当前路径 + 面包屑**。
- 顶栏收敛为：品牌 + 当前笔记面包屑 + 「＋新建」+ 命令栏（⌘K）+ 账号菜单。
- 引入 **24 个线性图标**（inline SVG）替换全部 emoji。

适合：**你现在每天在用的笔记本**。改完你会觉得"还是 WebBook，但终于安静了"。

### 方向二 · 纸墨（Ink & Paper）— 差异化最大

**把笔记本翻成浅色"纸"**，暗色作为夜间模式保留。

- 纸白 `#F4F1EA` + 墨黑 `#1B1A17` + 朱砂 `#A8442A`（仅用于状态/强调）。
- 层级靠**极细分割线与留白**，而不是卡片阴影——更接近实体笔记本的手感。
- 长文阅读与写作体验最好（对比度更高、更像纸）。
- 代价：画布/连线在浅色下需要重新设计（用网格纸 + 墨线表达，设计稿里有）。

适合：**白天长时间写文档**。但这是一次"换皮"，需要你接受它不再"暗黑高级"。

### 方向三 · 蓝图（Blueprint）— 技术舱

**面向"技术文档 + 知识图谱"的精密感**。

- 冷石墨底 + 青色强调（**注意：青色在这里是刻意的全局主色，不是画布私用**）。
- 网格底纹、等宽字体做元数据（路径/时间/SHA/块数）。
- 高信息密度但强对齐：8px 基线网格，所有面板共享同一套"仪器"式排版。
- 与方向一共享 80% 的组件结构，只换 token + 少量装饰。

适合：**把 WebBook 当工程知识库**的用法。你现在的目录（渲染/Gameplay/工具链）很像这个场景。

> **可以混搭**：最多人选的是 **方向一的外壳 + 方向三的画布**。
> 设计稿里三个方向是独立页面，混搭时告诉我取哪几块即可。

## 4. 不依赖方向选择的"必修项"

以下问题三个方向都要修，属于**不管选哪个都该做**的：

1. **补全 token 并接入**：`--fs-*`（含 11/12/13px 三档小字）、`--space-*`（补 6/10/14/18px）、
   `--radius-pill`、`--shadow-md-token`（现在 `0 4px 14px rgba(0,0,0,.35)` 手写了 7 遍）、
   `--stage-bg`、`--on-media`、`--handle`。
2. **删掉 33 处 `var(--token, #hex)` 兜底**，并把 `--muted` 改名成 `--text-muted`。
   这一条是"防止画布某天突然变蓝"的保险。
3. **统一图标**：24 个 inline SVG（folder / folder-open / file / plus / trash / pencil /
   check-square / clock / list-tree / chevron-* / search / command / sun-moon / user / logout /
   settings / external-link / grip / link / image / send / sparkles / alert / info）。
   全部 `aria-hidden` + 父级 `aria-label`。
4. **导航收口**：让 `/blog`、`/blog/u/*`、`/app/circles`、`/admin` 共用同一套外壳
   （或至少共用顶栏 + ⌘K）；顶栏给 active 态；`后台` 只对 admin 显示。
5. **移动端补底部导航**（笔记 / 任务 / 社区 / 我的），把「＋新建」做成悬浮主按钮。
6. **侧栏可读性**：宽度可拖拽（默认 280px，可存 localStorage）、
   深层级收窄缩进（14px → 10px 并可切"紧凑/宽松"）、当前路径自动展开。
7. **可访问性**：hover-only 工具条改为"始终可见但低对比 + hover 提亮"；
   补 `aria-label`；`window.confirm` 换成设计系统弹窗。
8. **空态升级**：游客进入 `/app` 给一个真正的"第一屏"——写第一句话的输入框，
   而不是两行灰字。
9. **首页收口**：先在 v4/v5/io-* /Swiss 里**定一代**，其余样式从 `layout.css` 删除（约 500 行）。

## 6. 施工中发现的既有问题（**不属于本次美化范围**，需单独决策）

### 6.1 舞台初始相机没有对准内容（明显，建议优先修）

新建 / 未拖动过的笔记打开后，正文在舞台里**偏到视口右侧之外**，只能看到左半截文字。

实测数据（1600×1000 视口，`/app/note/n1`）：

```
.stage-viewport   x=552  width=1032
.stage-world      transform: translate(50%, 50%) scale(1) translate(0, 0)
.stage-flow-column  宽 720，margin 0 155px ⇒ 落在视口 x=1223，右边界 1943
```

即：世界原点被映射到视口中心，而正文列相对世界原点有 `+515px` 的右偏移，
于是它从视口中心继续向右排，超出 `overflow:hidden` 的舞台边界被裁掉。

- 触发条件：`note.stage` 为默认值（`viewCenterX/Y = 0`）。
- 与本次美化**无关**：stage 几何与相机逻辑未改动，侧栏宽度、字号、圆角全部换算后与改动前等价。
- 疑似成因：`centerStageOn()` 的调用时机（放进"内容测量完成"之后），或 `viewCenterX` 初值应取内容中心而非 0。
- 影响：新建笔记第一眼就是半截文字，是当前最伤体验的一个既有 bug。
